# 私人数据与公开仓库

公开演示和私人部署请使用不同目录；不要把私人的云配置、照片或聊天放回用于发布的演示副本。

1. 复制或克隆项目到独立私人目录。
2. 执行 `python tools/prepare_private.py --confirm`。如果已经有 Git 仓库，它会取消跟踪演示数据路径，并增加 `.gitignore`；只改 Git 索引，不删除磁盘文件。提交前检查 `git status`。
3. 原图、聊天导出、增量、缓存、凭据和备份存到目录外，例如相邻的 `photo-planet-private/`。
4. 运行导入工具。新照片清单不保存本机源目录或原文件名，但图片画面、EXIF 派生日期、聊天正文仍属于私人内容。
5. 使用受保护的部署入口发布。默认演示 Docker 和普通静态托管都没有登录保护。

`prepare_private.py` 不会抹除历史提交里的内容。如果误提交了私人文件，应清理历史；如果误提交了有效凭据，先吊销／轮换凭据，再清理仓库。

## 浏览器存储

昵称、布局和主题在 localStorage；自加照片在 IndexedDB；私有 OSS 照片可有受登录检查的 CacheStorage 缓存。清理浏览器会丢失其中部分数据。共享设备使用完后应退出站点，并按需清理站点存储。

只在前端换显示昵称，不会修改聊天正文。不要认为替换昵称就已匿名化真实聊天：正文、引用、链接、文件名和照片本身都可能识别人。本公开版的聊天是重新编写的合成内容，不是实际聊天的简单替换。

## 发布前

运行 `python tools/check_public.py` 并人工查看图片、文档及 staged diff。扫描只是辅助，不能证明任意私人导入已经脱敏。公开演示的截图也必须使用虚构数据生成。
